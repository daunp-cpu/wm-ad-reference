# Claude 직접 복각 지시서 (SOOO·BH 공통)

너는 지금 광고 레퍼런스 복각 사이트(SOOO 또는 BH)에서 들어온 요청 1건을 **직접** 만든다. Gemini 자동 복각은 쓰지 않는다(다운: "제미나이 퀄리티 떨어지니까 무조건 너가 해"). 어떤 도구를 쓸지는 네가 정한다.
대화 상대는 없다(혼자 끝까지). 설명·로그는 한국어.

## 입력
- `brief.json` (작업폴더 안): site, type(bokgak/retry/revise), facts(제품 사실), check(본문 체크 문구), default_landing, product_photos(실제 제품 사진),
  items[]: ref_video/ref_image(레퍼런스 파일), ref_memo(레퍼런스에 단 메모), ref_text(광고 문구), landing, assets[](다운이 올린 쓸 에셋 — lab U1·R1·F1, path, kind), docs[](기획안 = 지시서), asset_note.
  revise 면: feedback(이번 피드백), prev_feedback(이전 피드백 — 전부 계속 지킴), base_img/base_mp4(지금 버전), plan, ref(레퍼런스), new_assets.
- `command` (복각 창의 **'명령어 입력'**): 다운·팀이 너에게 직접 쓴 편집 지시. **가장 먼저 읽고 최우선으로 지킨다** — 문구·가격·글꼴·컷 순서·쓸 에셋 등 적힌 건 글자 그대로. 지키지 못한 게 있으면 result note 에 이유를 적는다.
- 명령어 입력 > 메모·기획안 > 레퍼런스 > 네 판단 순으로 따른다. 메모의 문구·가격은 글자 그대로.

## 출력 (반드시)
작업폴더에 `result.json` 을 쓴다. 이것만 있으면 사이트 반영·배포는 작업기가 한다(네가 review.json·배포·메타는 건드리지 않는다).
```json
{"ok": true, "items": [{"ref_id": "…", "kind": "image|video",
  "img": "작업폴더/out/대표컷.jpg (영상이면 대표 장면 jpg, 이미지면 1080x1350 등 완성 이미지)",
  "mp4": "작업폴더/out/final.mp4 (영상일 때만)",
  "soguo": "소구점 2~6자", "hook1": "본문 후킹 1줄", "hook2": "본문 후킹 2줄", "headline": "화면 큰 문구", "sub": "화면 작은 문구",
  "format": "형식 한 줄", "why": "레퍼런스가 오래 도는 이유 한 줄", "body": "(선택) 광고 본문 전체 — 기본 상품이 아니면 그 상품용으로",
  "landing": "랜딩 URL", "landing_title": "상품명 (번호)", "note": "무엇을 어떻게 만들었는지 — 쓴 에셋·도구·비용", "summary": "(수정일 때) 이번에 고친 점"}],
 "err": ""}
```
못 만들면 `{"ok": false, "err": "이유(사람이 읽을 한 줄)"}` — 촬영이 필요한 장면이 있으면 err 에 무엇을 찍어야 하는지 적는다.

## 시간 단축 (방법·품질 기준은 그대로, 시간만 줄인다) — 2026-11-04 다운 "퀄리티는 유지하되 더 빨리, 토큰 많이 써도 돼"
실측: 한 건 시간의 70~80%가 **너의 턴 수(100~190번)와 출력 토큰(6~9만)**이었다. 도구 실행은 20~30%. 그래서 아래를 지킨다.
- **한 번에 여러 개 부르기**: 서로 상관없는 도구 호출(파일 여러 개 Read, 이미지 여러 장 보기, 독립된 Bash)은 **한 응답에 같이** 보낸다. 하나 보고 다음 하나 부르지 않는다.
- **명령은 묶어서**: 렌더 → 길이 확인 → 프레임 뽑기 → 받아쓰기는 Bash 한 번에 `&&` 로. 작은 확인(ls·ffprobe 하나)마다 턴을 쓰지 않는다.
- **검수는 `qc.py` 한 번**: `/Users/daun/meta-ads/.venv/bin/python -I ~/ad-reference/claude_kit/qc.py out/final.mp4 --ref <레퍼런스> [--t 1.0,5.5,12]` → `qc_cmp.jpg`(같은 시각 레퍼런스|결과 나란히, 프레임 동시 추출) + `qc_sheet.jpg` + 받아쓰기를 2~25초에 한꺼번에. 비교 이미지를 따로 짜 맞추는 코드를 새로 쓰지 않는다. 이미지 복각도 `qc.py 결과.jpg --ref 레퍼런스.jpg`.
- **미리 만들어 둔 것 그대로 쓰기** (`brief.pre`): 레퍼런스·지금 버전의 0.5초 시트(`sheet`), 컷 경계(`cuts`), **받아쓰기 단어 시각(`words` 파일)**. 다시 만들지 않는다.
- **수정(revise)이면** `brief.base_copied`(= 작업폴더/w, 이전 버전 편집 코드·재료를 이미 복제해 둠)에서 바로 시작한다. 편집 코드는 **Edit 로 고칠 줄만** 바꾼다 — 전체를 다시 쓰지 않는다(출력 토큰이 가장 큰 시간). 레퍼런스 실측·에셋 탐색은 피드백이 그 부분을 지적할 때만 다시. base_copied 가 없고 base_work 만 있으면 거기서 복사.
- base_work 가 없으면(사람이 채팅에서 만든 버전 등) base_mp4·base_img 를 출발점으로, 바꿀 구간만 다시 만든다.
- **드라이브 에셋은 `brief.drive_index`(data/drive_index.json, 매일 갱신) 목록에서 먼저 고른다** — 매번 폴더를 훑지 않는다. `local` 이 있으면 그 파일을 바로 쓰고, 없으면 `gdrive.py get <id> <경로>`(받은 건 `~/ad-reference/data/drive_cache/` 에 두면 다음부터 local 로 잡힘). 루트 = 광고주 에셋(시딩·제품·신뢰) `YOUR_DRIVE_FOLDER_ID_1`, WM 에셋(촬영·제작, 261028 두피관리샵 촬영·샴푸 제형·승무원·AI 영상 등) `YOUR_DRIVE_FOLDER_ID_2`.
- **`brief.warn` 이 있으면 먼저 읽는다**(예: 구글 인증 만료 → 드라이브·Vertex 안 됨). 막힌 도구를 여러 번 시도하지 말고 바로 대안(로컬 에셋·ZCRE)으로.
- 확인용 렌더는 540px·`-preset ultrafast`(또는 `-c:v h264_videotoolbox`)로 빠르게, **마지막 한 번만** 1080px·원래 설정으로. 프레임 확인은 필요한 시각만 `-ss` 로.
- **오래 걸리는 일은 뒤에서**: AI 생성 대기·고화질 렌더·여러 컷 렌더·에셋 다운로드는 `&` 후 `wait` 로 동시에, 그동안 다른 장면 작업을 한다. 생성(AI)은 기존 저장본(data/keyframes, data/veo)이 있으면 재사용.
- **보조 에이전트(Agent) 써도 된다**(토큰 더 써도 됨): 서로 독립인 큰 일 — 예: ① 드라이브 에셋 후보 고르기(시트 보고 추천 3개) ② 내레이션·자막 대본 다듬기 ③ 특정 장면 그래픽 만들기 — 을 동시에 맡기고 너는 편집을 계속한다. 맡길 땐 파일 경로·조건·결과 형식을 분명히 주고, 결과는 네가 qc 로 확인한다. 작은 일(파일 하나 읽기 등)은 맡기지 않는다. 부를 땐 반드시 `model: "sonnet"` 을 넣는다(비용, 2026-11-11).
- 품질 확인 횟수(비교 최소 2번)는 줄이지 않는다 — 대신 한 번의 확인을 qc.py 로 빠르게.

## ✍️ 카피 쓰는 법 — ZET 방식 (2026-11-09 다운: "ZET 카피가 기가 막히게 혹한다, 그 룰 적용해")
ZET 기획서 65개를 뜯어보니 카피가 좋은 이유는 모델이 아니라 **순서와 제약**이었다. 화면 글씨(헤드·서브·뱃지·가격·CTA·자막)와 hook1·hook2·headline·sub 전부 이 순서로 쓴다.
명령어 입력·메모·기획안에 적힌 문구는 글자 그대로 쓰고, 아래 과정은 **비어 있는 자리**에만 적용한다.

1. **고객 장면부터 읽는다** — `<사이트>/data/copy_brief.md`(기본 상품의 타겟·고객 말투·대안의 한계·소구점 뱅크). 기본 상품이 아니면 랜딩을 읽고 같은 형식으로 짧게(타겟 2명 × 소구점 3개) 작업폴더에 `copy_brief.md` 를 먼저 쓴다.
2. **레퍼런스 문구 해부표**를 만든다 — 화면의 모든 글씨를 슬롯으로 쪼갠다:
   `위치·역할(엠블럼/서브/메인/뱃지/가격/CTA/자막n) | 원문 | 글자수(공백 포함) | 줄 수·줄바꿈 위치 | 문장 골격 | 설득 장치`
   - 문장 골격 = 품사 순서와 기호. 예: `[고통]+[고통]` / `[동사]-[명사]` / `~하는 [제품명]` / `… [결과]!` / `[ 대괄호 ]` / `★ ~ 중 ★`
   - 설득 장치 이름을 붙인다: 고통 호명 · 타깃 호명 · 라임/말장난(땀쟁이도 쟁이는) · 신조어 비유(바디가글) · 숫자 증명 · 단위 가격(1포 800원대, 개당 2만원대) · 권위(박사·인증) · 긴급/한정 · 고객 감탄체("이제 이거 없이 ~ 못해요") · 대체 비교(○○ 대신!) · 즉시성(눕기만 하면, 3초).
3. **타겟 1명 + 핵심 소구점 1개**(+보조 최대 2개)를 copy_brief 소구점 뱅크에서 고른다. 레퍼런스의 설득 장치와 가장 잘 맞는 것으로. 소구점을 여러 개 섞지 않는다 — 3초 안에 하나만 남게.
4. **1차 카피** — 제약 없이 가장 혹하는 버전. 기능어(이중열선·콩제비꽃 추출물) 말고 **고객이 실제로 하는 말과 장면**(냉골 침대, 가스비 고지서, 정수리 열감, 엘리베이터 거울)으로. 숫자는 FACTS 에 있는 것만.
5. **최종 카피** — 1차를 레퍼런스 틀에 끼워 압축한다:
   - 슬롯마다 **글자수 ±10%**, **줄 수·줄바꿈 위치·문장 골격·기호 그대로**, 설득 장치 유지 — 내용만 우리 소구점으로 교체.
   - 1차 카피에서 핵심 단어만 남기고 조사·수식어를 깎는다. 구어체. 어려운 용어 금지.
   - 레퍼런스 브랜드명·레퍼런스 실적(1위·누적 N개·연구원 PICK 등)은 우리 근거가 없으면 우리 근거 있는 다른 권위(화학박사 개발·특허 성분·KC 인증·국내 제작 등)로 바꾼다. 없으면 그 슬롯은 장치만 살려 다른 말로.
6. **자가 검증** — result note 에 표를 남긴다: `슬롯 | 레퍼런스 원문(글자수) | 최종(글자수) | 쓴 장치 | 근거`. 하나라도 걸리면 고친다:
   ① FACTS 에 없는 숫자·순위·인증이 들어갔나 ② 금지 표현(의약품 표현 등) ③ 레퍼런스보다 글자가 많아 줄이 늘었나 ④ 소구점이 두 개 이상 섞였나 ⑤ 소리 내 읽었을 때 광고 문구가 아니라 사람 말처럼 들리나.
- hook1·hook2(본문 첫 두 줄)도 같은 원리: 1줄 = 타겟의 속마음·장면 인용, 2줄 = 소구점 + 숫자 하나.
- ZET 실제 예(장치는 그대로, 내용만 교체):
  - "땀쟁이도 쟁이는 / 바디가글 스크럽" → "맛있어서 쟁이는 / 여배우 PICK 애사비" (라임 + 박스 강조 유지)
  - "이제 이거 없이 / 샤워 못해요" → "이제 이거 없이 / 식단 못해요" (고객 감탄체, 줄바꿈 위치 동일)
  - "★ 실시간으로 재고 없어지는 중 ★"(14자) → "★ 실시간으로 재고 소진되는 중 ★"(14자)
  - 🔴 ZET 는 근거 없는 말도 지어냈다("30년 한일기술", "자취생 PICK", "라돈 불검출") — **우리는 장치만 빌리고 사실은 FACTS 로만.**

## 🖼️ 이미지 복각 필수 규칙 — 전부 지켜서 만든다(어긋난 게 보이면 고쳐서 올린다) (2026-11-10 다운: "글씨체 바꾸지 말고, 제품 위치 바꾸지 말고, 누끼 딴 거 같지 않게, 레퍼런스랑 똑같이" — 팀원들도 퀄리티 낮다고 함)
이미지(정지 이미지·캐러셀·GIF 프레임) 요청이면 **먼저 메모리 `image-creative-playbook.md`(1차 완성 규칙·밤티 목록·검수 10항목)와 `image-creative-recipes.md`(통과한 유형별 코드·폰트 매칭표)를 읽고**, 아래를 전부 지킨다. 명령어 입력·메모가 다르게 시키면 그쪽이 우선.
1. **레이아웃 = 레퍼런스 그대로.** 제품·글씨·여백의 위치와 크기 비율을 레퍼런스 실측값(100px 눈금)과 맞춘다. 제품 위치·크기를 옮기거나 바꾸지 않는다. 글씨 줄 수·줄바꿈 위치·정렬도 같게.
2. **글씨체 = 레퍼런스 그대로.** 같은 글씨체·굵기·색·크기 비율(규칙 1의 후보 글꼴 나란히 비교로 고른다). 임의로 다른 폰트로 바꾸지 않는다.
   - AI(나노바나나 등)가 그린 글씨는 쓰지 않는다 → **글씨 없는 배경**을 만들고 글씨는 실제 폰트로 PIL 로 얹는다.
   - 레퍼런스에 없는 외곽선·그림자·도장·형광 강조를 넣지 않는다. 강조색은 레퍼런스처럼 한 곳만.
3. **제품은 실제 촬영한 것처럼 — 누끼 붙인 티 금지.** 장면과 같은 빛 방향·접지 그림자·반사·색온도·초점을 맞춘다. 흰 테두리·뜬 그림자·다른 조명이면 실패.
   - 장면 안에 자연스럽게 넣어야 하면 나노바나나/ZCRE 에 [레퍼런스(분위기용) + 실촬영 제품 사진 + 제품 누끼]를 넣어 장면째 생성하고, **라벨을 확대해 실물과 다르면 그 부분을 실제 사진으로 덮는다.**
   - 라벨·로고·글자는 실물과 똑같아야 한다. 없는 박스·라벨·스포이드병을 지어내면 실패. 장면 컷은 **샴푸 한 병만**, 세트 구성 컷일 때만 앰플·괄사·브러시 실제 사진을 각각 참고로 넣는다(BH 는 실제 제품 사진만).
4. **분위기는 가져오고 주인공은 우리 제품.** 레퍼런스의 빛·색감·톤·구도만 가져온다. 다른 업종 피사체(모델·옷·소품)를 따라 하지 않는다. 장면은 제품 쓰는 맥락으로.
5. **문구는 짧고 자연스럽게.** 레퍼런스 문장 구조(줄 수·리듬·강조 위치)는 살리되 우리 제품·가격·혜택으로. 레퍼런스 문장을 억지로 끼워 넣지 않는다. 근거 없는 1위·최초·100% 금지(규칙 5).
6. **검수:** (먼저 🎨 브랜드 번역 자가 검수 — 로고 가려도 우리 광고로 보이는가) 완성본과 레퍼런스를 **같은 크기로 나란히** 붙인 비교 이미지를 만들어 직접 보고 아래 6개가 전부 '같다/통과'일 때만 ok:true. 하나라도 아니면 고치고 다시 비교(최소 2번).
   ① 제품 위치·크기 ② 글씨체·굵기 ③ 글씨 위치·줄바꿈·색 ④ 색감·빛 ⑤ 누끼 티 없음(제품 가장자리 2배 확대) ⑥ 라벨 글자 실물과 같음(라벨 확대).
   note 에 이 6개 결과를 한 줄씩 적는다.
